# M10 manual test — toolpath playback

**Why this document exists.** M3 left a question open in `m3.md`: *"no playback, only scrubbing — the
timeline has no play button (M4 decides whether it needs one)"*. M4 never did, and the reason the question
was hard is exactly the reason it cannot be settled by a test. Whether the clock advances correctly, stops
at the end, refuses an untimed program and puts the marker on the chord is all unit-tested. What only a
human can judge is whether **watching it run tells you anything you did not already know from scrubbing** —
whether the marker is findable against a dense path, whether the editor following along helps or distracts,
and whether any of the four speeds is the one you would actually use.

Read `m3.md` first if you have not; this only covers what M10 added. About fifteen minutes.

## Setup

```bash
.venv/bin/foursight-gui tests/fixtures/baseline_4axis.nc
```

The transport sits at the left of the timeline bar, under the toolpath: play/pause, back-to-start, and a
speed selector.

---

## 1. The transport does what it says

| Step | Expect |
|---|---|
| Press play | The marker starts moving along the path; the handle slides; the readout counts up |
| Press play again | Everything stops where it is — the marker stays put, the readout holds |
| Press play a third time | It carries on from where it stopped, not from the beginning |
| Let it run to the end | It stops on its own; the button shows **play** again, not pause |
| Press play at the end | It rewinds and starts over |
| Press back-to-start mid-run | Marker at the beginning, stopped, editor back at the first motion line |
| Press `Ctrl+Space` | Same as clicking play. Then click into the code and press plain **Space** — it must type a space, not toggle playback |

**The property being checked:** every control does one thing and says which. A play button that lights up
and does nothing, or one that stops at the end while still showing "pause", is the kind of defect that
makes a user distrust the whole preview.

## 2. The marker is findable

| Step | Expect |
|---|---|
| Play at 1× and watch the marker | A white dot, clearly the brightest thing on screen, distinct from red rapids, green feeds, amber unverified spans and the cyan selection |
| Orbit the view while it plays | The marker keeps its size — it does not shrink with distance |
| Zoom right in, then right out | Still the same size on screen, still findable |
| Find a moment where the tool is below the top of the path and rotate so geometry is in front of it | **The marker still shows through.** It must not disappear behind the toolpath |

**The property being checked:** the marker is *view state*, like the selection highlight — it must never be
mistaken for geometry, and it must never be hidden by geometry. A marker that vanishes into the work reads
as the program having finished. If you cannot find the dot on a dense path, that is a real finding.

## 3. The editor follows

| Step | Expect |
|---|---|
| Play and watch the code pane | The cursor walks down the program; the current line stays highlighted and in view |
| Watch during a single long move | The pane does **not** re-centre repeatedly while the tool works along one line — it should sit still until the line changes |
| Watch the toolpath at the same time | The cyan highlight follows the same line the cursor is on |
| Click a line in the editor while playing | Playback carries on and takes the cursor back on the next line change |

**The property being checked:** this is the reason a player belongs in an editor rather than in a viewer.
If the code scrolling past does not help you understand what the tool is doing, say so — that is a finding
about the feature, not a bug.

## 4. Speed

| Step | Expect |
|---|---|
| Play at 1× | Real time. The readout matches a stopwatch |
| Switch to 10×, then 100×, while it plays | The rate changes; the position does **not** jump |
| Switch to 1000× | The whole fixture is over almost at once |
| Watch the readout at every speed | It always reads **program** time — the cycle time, never wall-clock elapsed |
| Change speed, apply a fix (Fix ▸ Normalize whitespace), and play again | The speed you chose is still selected |

**The property being checked:** the multiplier changes how fast you watch, never what you are told. A
readout that sped up with the playback would be reporting a cycle time that is not the program's.

## 5. Scrubbing and playing together

| Step | Expect |
|---|---|
| Start playing, then grab the handle and hold it still | Playback **waits** — the handle stays where you put it and the marker stops running away |
| Still holding, drag forward and back | The marker follows your drag in both directions; the editor keeps up |
| Let go | Playback resumes from where you dropped it, with no jump forward |
| Drag backwards to review a move, then let go | It plays that move again from there |
| Click on the slider groove (not the handle) | It jumps there and keeps playing |

**The property being checked:** dragging mid-run is a *seek*, not a stop. Watch particularly at **1000×** —
if the handle fights you or the position runs off while you are holding it, that is a real defect.

## 6. Programs that cannot be played

| Step | Expect |
|---|---|
| Open a program with no feed rate: `printf 'G21 G90 G94\nG1 X10\n' > /tmp/nof.nc` then open it | Play, back-to-start, speed **and** the slider are all greyed out |
| Press `Ctrl+Space` on it | Nothing happens — no marker, no motion |
| Open a program where only *some* moves have a rate | It plays, and the readout still ends with "… segments without a feed rate — total is short" |
| Open `tests/fixtures/canned_cycle_span.nc` and play | The suppressed span is not drawn and the marker does not travel through it |

**The property being checked:** the two honesty constraints from M3 survive playback. A partial total is
never presented as the cycle time, and a program with no time to play refuses plainly rather than sweeping
the marker to the end in one frame.

## 7. Playback and the rest of the window

| Step | Expect |
|---|---|
| Pause mid-program, then press `Ctrl+P` (part coordinates) | The marker **stays visible** and moves onto the part-coordinate path with the toolpath — it does not vanish or float beside it |
| Press `Ctrl+P` again | It comes back to the machine-coordinate path |
| Play, then apply a fix while it is running | Playback stops and rewinds to the start; the marker is gone until you play again |
| Play, then open a different file | Same: stopped, at the start, no stale marker from the previous program |
| Play, then close the window mid-run | It closes cleanly, with no hang |

**The property being checked:** a playback position belongs to one program's timeline. Anything that
replaces the program must take the position with it — a marker left riding a timeline that no longer
describes what is on screen is precisely the confidently-wrong output the plan forbids.

## What is deliberately absent in M10

Not bugs. Do not file these:

- **No travelled-versus-remaining trace.** The whole path stays one colour scheme; only the marker moves.
  Re-colouring the travelled prefix needs either a per-vertex colour buffer (16 MB at 500k segments) or a
  full-size overlay re-uploaded every frame, and neither is within the memory budget in `PLAN.md`
  § Performance Requirements.
- **No step-by-segment control.** It would be the honest complement to the limitation below, but it needs
  an index-indexed position rather than a time-indexed one. The editor and click-to-pick reach those moves.
- **Zero-duration segments are skipped instantly.** A dwell or a stationary block occupies one instant, so
  several segments share a cumulative time and no playback position lands on them. Inherent, documented in
  `PLAN.md` § Timeline since M3.
- **G4 dwells cost no playback time.** The dwell is computed but never reaches `SegmentStore.duration`, so
  playback runs straight through one. Recorded in `TASKS.md` § M10.
- **No bare Space shortcut.** The editor is a text pane and Space types a space. Use `Ctrl+Space`, or give
  the play button focus and press Space there.
- **The marker is a position, not a tool.** No holder, no diameter, no collision shape — a tool library is
  post-v1 (`PLAN.md` § Future).
